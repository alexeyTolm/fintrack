# Личный финансовый учет

Полноценное веб-приложение для учета личных доходов и расходов: регистрация/вход,
дашборд с графиком, CRUD операций с фильтрами, планы трат по категориям с прогресс-барами,
экспорт отчетов в Excel, страница аналитики с диаграммами.

Реализовано строго по присланному ТЗ.

## Стек

- **Backend:** Python + FastAPI, SQLAlchemy, SQLite (по умолчанию), JWT-авторизация, bcrypt.
- **Frontend:** чистые HTML + Bootstrap 5 + JavaScript (без сборки), Chart.js для графиков.
- **Экспорт:** openpyxl генерирует `.xlsx` на лету.

## Запуск backend

Требуется Python 3.10+.

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # при желании поменяйте SECRET_KEY
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

После запуска:
- API доступно на `http://127.0.0.1:8000`
- Интерактивная документация (Swagger): `http://127.0.0.1:8000/docs`
- База данных SQLite (`fintrack.db`) создается автоматически при первом запуске.

**Важно:** в `.env` обязательно задайте свой `SECRET_KEY` (любая длинная случайная строка) —
это ключ для подписи JWT-токенов.

## Запуск frontend

Frontend — статические файлы, backend им не раздается, поэтому нужен любой простой
статический сервер (открывать файлы напрямую через `file://` нельзя из-за CORS/fetch).

Проще всего через Python:

```bash
cd frontend
python3 -m http.server 5500
```

Откройте `http://127.0.0.1:5500` в браузере.

Если backend работает на другом адресе или порту — измените `API_BASE_URL`
в файле `frontend/js/config.js`.

## Проверка сценария приемки

1. Откройте `http://127.0.0.1:5500`, зарегистрируйте нового пользователя.
2. После входа откроется дашборд с нулевыми показателями.
3. Перейдите на вкладку «Операции», добавьте 2–3 дохода и 3–4 расхода в разных категориях.
4. Вернитесь на дашборд — увидите обновленный баланс, суммы за месяц и график расходов по дням.
5. На вкладке «Планы трат» задайте лимит для категории (например, «Еда» — 10000 ₽) —
   появится прогресс-бар (зеленый / желтый от 80% / красный при превышении).
6. На вкладке «Отчеты» нажмите «Скачать отчет (Excel)», выберите период — скачается
   `.xlsx`-файл с операциями и итоговыми суммами.
7. Зарегистрируйте второго пользователя — убедитесь, что он не видит операции первого
   (данные изолированы по `user_id` на уровне каждого запроса к БД).

## API-эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/register` | Регистрация нового пользователя |
| POST | `/api/login` | Вход, возвращает JWT-токен |
| GET | `/api/profile` | Данные текущего пользователя |
| GET | `/api/categories` | Список категорий доходов/расходов |
| GET | `/api/dashboard` | Баланс, суммы за месяц, график по дням, последние операции |
| GET/POST | `/api/transactions` | Список (с фильтрами) / создание операции |
| PUT/DELETE | `/api/transactions/{id}` | Изменение / удаление операции |
| GET/POST | `/api/plans` | Список планов на месяц (с прогрессом) / сохранение лимита |
| GET | `/api/export` | Скачивание Excel-отчета за период |

Все эндпоинты (кроме `/api/register` и `/api/login`) требуют заголовок
`Authorization: Bearer <token>`.

## Безопасность

- Пароли хранятся только в виде bcrypt-хешей.
- Каждый SQL-запрос к транзакциям и планам фильтруется по `user_id` текущего
  авторизованного пользователя — доступ к чужим данным невозможен.
- Используется SQLAlchemy ORM с параметризованными запросами (защита от SQL-инъекций).
- JWT-токен передается в заголовке `Authorization`, срок жизни настраивается через
  `ACCESS_TOKEN_EXPIRE_MINUTES` в `.env`.

## Известные упрощения (можно доработать)

- Восстановление пароля не реализовано (в форме входа есть ссылка-заглушка).
- Пользователь не может создавать собственные категории — список зафиксирован в
  `backend/app/constants.py` согласно ТЗ.
- CORS в `main.py` открыт на `*` для удобства разработки — перед продакшен-деплоем
  укажите точный домен фронтенда в `allow_origins`.
